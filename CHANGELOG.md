# Changelog

What shipped, and why. Newest day first.

This is the project's own record rather than a release log: DevProMax is one
local application with no versions to publish, so what is worth keeping is the
reasoning behind each change - the thing a diff cannot carry. Entries are keyed
by the ROADMAP task they close, so the plan and the history point at each other.

It lived in `ROADMAP.md` section 7 until 2026-09-18 (P8-4), by which point fifty
entries had made the plan's last section longer than the plan. The days are
newest first; within a day, entries are in the order they were written, which is
how they arrived in that section and not worth rewriting after the fact.

## 2026-09-24

- **P10-4** — `npm run package:win` builds a folder that runs DevProMax on a Windows machine with nothing installed: Node 24.21.0, Python 3.13.15 from python-build-standalone and a jlinked Temurin 25, each pinned by hash, beside the built app, its production dependencies and the catalogue. Checked the way a stranger's machine would check it: with only Windows on `PATH`, every `DEVPROMAX_` variable set to something wrong, and `LOCALAPPDATA` under a folder named in Chinese, the bundle started, its doctor named its own three runtimes, and reference solutions were Accepted in both languages, a custom checker's problem among them. 341 MB. Two surprises. The JDK came out at 90 MB rather than the 46 measured for the plan, because the class-data-sharing archive comes in two copies; the one for heaps past 32 GB can never load at the judge's 256 MB and went, and the other stayed because it takes javac's start from 362 ms to 235 ms, which every Java Run pays. And the check that refuses test files found 856 of zod's, which it publishes with its source; dependencies now ship without their tests rather than the rule growing an exception.
- **P10-3** — the launcher, what a Start menu shortcut will run: it starts the server if it is not running, waits for `/health`, and opens the browser. An installed copy overrides the user's own `DEVPROMAX_*` variables instead of deferring to them - the home server's global `DEVPROMAX_PYTHON` would otherwise have an installed copy judging with uv's Python - and keeps its data under `%LOCALAPPDATA%\DevProMax`, outside the program directory. The port is remembered, because a wandering port is a new origin and a new origin has lost the theme and the welcome flag; a second click finds its own server on it and only opens a tab. The console shows the address and how to stop, and on a failed start stays open until a key is pressed rather than flashing shut. Backup, restore and the doctor are subcommands, for users who have no `npm`. `npm run launch` runs it from a checkout. The plan's 8.3 short name for an unrepresentable data directory turned out unnecessary: after P10-1 nothing names that directory on a command line.
- **P10-2** — the server, ready for a launcher to start it. `/health` now says whose it is and which version, because a launcher that finds something on its port has to know whether it is its own server. The version is one number, the root `package.json`, now `1.0.0` to match release 1.0; the workspaces follow it, the start-up line and a new Settings › About card show it, and the installer and release tag will read the same field. Production stopped logging every request: two lines of JSON per page load were scrolling the address and any runtime warning out of the only window an installed user sees. `DEVPROMAX_LOG_FILE` puts the log in a file instead, rotated at start-up, so a bug report has something to attach. And with `DEVPROMAX_BUNDLED=1` the app stops giving advice an installed user cannot follow - install Python, set `DEVPROMAX_PYTHON`, run `npm run db:backup` - and says to reinstall over the copy, or where the Start menu's backup is.
- **P10-1** — Java failed outright for anyone whose data directory sits under a name the Windows ANSI code page cannot spell, which is everyone whose account name is outside it: Windows hands a JVM its command line in that code page, so a workspace under `测试` reached `javac` as `??`. Reproduced on the home server before touching anything, with Python passing beside it. The local launcher now names every file relative to the workspace it runs in - sources, class path, payload, and the shared harness cache two directories up - so the path's awkward part is never on a command line. That fixes the data directory; it cannot fix a JDK installed under such a name, because the JVM expands its own home and fails to find `java.dll` whatever it is called as. So the doctor now resolves `java` and `javac` the way `spawn` would, checks the path against the code page read from the registry, and says which characters are the problem instead of passing on the JVM's complaint. The rule is built from the WHATWG decoders rather than a hand-kept table, and the launcher and installer will reuse it.
- **P10 planned** — how people who are not the developer get DevProMax: a per-user Windows installer that bundles Node, Python and a jlinked JDK, and a launcher that starts the server and opens the browser (D26, milestone M6, tasks P10-1 … P10-11). The plan was audited against the code before it was written down, and the audit changed it. A JDK or a judge workspace under a path the ANSI code page cannot represent breaks Java outright - reproduced, and a bug for today's users too, so it is P10-1. The launcher has to override the user's own `DEVPROMAX_*` variables, and has to keep the port stable because the theme and the welcome flag are per-origin `localStorage`. Installed users have no `npm`, so backup, restore and the doctor go through the launcher. Production request logs would scroll JSON through the only window a user sees. Smart App Control blocks unsigned executables outright, python-build-standalone's included. And the estimate grew to roughly 330 MB installed, because `problems/` is 110 MB of hidden tests. One risk was cleared by measurement: a JDK cut to `java.base` and `jdk.compiler` is 46 MB and still compiles `--release 21`.
- **M5.1** — a whole-codebase audit before the owner puts a real API key in for the first time. Seven reviews ran in parallel - judge, server, coach, workspace, the other screens, the catalogue, and tests and CI - each told to cite the line and to read the recorded decisions first so a deliberate choice was not reported as a bug, beside a full baseline run on the home server: lint, types, 1,671 unit and integration tests, all 171 problems validated, 87 end-to-end tests and Lighthouse. The baseline was nearly green - one Java test judged TLE under load, and the workspace at 87-88 against Lighthouse's 90 - and the reviews found what a green baseline cannot: 114 findings, among them a percent-encoded path that walked past the API hardening, a settings write that deleted the stored key, a structured-output schema the real Messages API would have refused on every AI Help, an autosave that could file one problem's code under another's name, and an end-to-end suite that blanked the owner's key whenever it ran beside `npm run dev`. They became twenty tasks, P3-8 … P8-8, fixed by seven agents working on disjoint files, each finding closed with the test that would have caught it.
- **P3-8** — The client-header and JSON-only checks compared the raw URL with `/api`, but the router decodes paths before matching, so `/%61pi/settings/reset-progress` reset progress from a cross-origin form. The checks now ask what the router matched, falling back to a generously normalised path - wrongly treating a path as API costs a 403 on what would have been a 404. Fastify's built-in `text/plain` parser is gone. A test that built the server without a database had been migrating the owner's real `data/devpromax.db` on every run, so opening the default database under Vitest now throws, and the next such test fails loudly instead of quietly. D15 updated: its checks were described as each sufficient alone, and one was only as good as its idea of which requests it covered.
- **P3-7** — Changing the coach model deleted the stored API key. In zod 4 a `.default()` still fires inside `.partial()`, so a one-field PUT came back with every sibling in that section set to its default, and the repository merged those over the stored values - saving a key reset the provider, a font-size change reset the tab size. The patch schemas are now built from the section schemas with the defaults removed rather than with `.partial()`, so a patch carries exactly what the client sent; the fix lives in the schema rather than the merge, because a patch type that invents fields is wrong wherever it is read. On the screen, every write the server refuses is shown in the card that made it - with no Save button, a change that silently did not happen looks exactly like one that did - number fields refuse fractions where the schema wants an integer, the key field clears only once the server has confirmed the key, and changing provider also clears the model. There is still one key slot and the server cannot tell whose key it holds, so the screen says keys are per vendor and, after a switch, that the stored one may belong to the old provider. "Add a key first" is written in the row; it was a tooltip on a disabled button, which can never be hovered or focused.
- **P8-6** — The e2e suite runs on its own ports - Vite on 5183, the API on 5184 - and never reuses a running server. `reuseExistingServer` used to hand it whatever `npm run dev` was running, and with it `data/devpromax.db`: `coach.spec.ts` saves an empty API key, which deleted the real one, and the draft specs deleted real drafts. The API and Vite are two web servers, the API waited on at `/health`, so a stranger on the API port is an error rather than something Vite quietly proxies to. `data/e2e.db` is emptied before every run by `e2e/reset-db.mjs`, as part of the API's start command rather than a `globalSetup` - Playwright starts web servers before global setup, and by then the file is open - and it refuses any file not named `e2e.db`. The a11y interview audit skips only on the one refusal it means and fails on anything else.
- **P5-11** — The first read of the coach against the real Messages API rather than recorded fixtures found that every AI Help would have been refused: zod's JSON Schema carries `$schema`, length and range limits, `default` and no `additionalProperties: false`, and structured outputs refuse all of them. The schema now goes through the SDK's own transform, so the vendor's rules are the vendor's copy rather than a second copy of ours that goes stale; the constraints it drops move into field descriptions and are still enforced when zod parses the answer. Requests depend on the model: a capability map beside the price table gives adaptive thinking and effort only to models that take them, so Haiku 4.5 gets neither (it rejects both with a 400), and an id the map cannot read is treated as not thinking, because that is the request every model accepts. Errors say what to do: a 404 names the missing model, a 400 carries the vendor's own explanation (trimmed, key scrubbed) because only the vendor knows which part was wrong, mid-stream overloads are retryable instead of "failed unexpectedly", and a refusal is final and says the key is fine. A stream that goes silent is abandoned after 90 s - the watchdog counts bytes, not events, because the SDK hides pings, and the old 300 s timeout only ever covered the headers. Streams retry once, not twice, since every retry is a whole new billed turn. One helper decides where each provider lives: the connection test used to send a leftover local URL to Anthropic, and turns ignored the OpenAI-compatible address the test had just approved. D12 updated.
- **P5-12** — The "Latest judge result" section never had a source, so every review said the code had never run, even straight after an Accepted. It now reads the latest submission, but only as evidence about the code it came from: if the editor has moved on, the coach is told the verdict was for different code, so it does not chase a bug that has already been fixed. Follow-up questions were answered under a prompt that ends "return JSON" with no schema attached; an uncached second system block now asks for prose and keeps the ladder and the solution gate. It stays outside `PROMPT_VERSION`, because it changes the format rather than the advice and nothing it produces is scored. The server enforces the solution gate itself rather than trusting the model. Interviews have their own session kind (migration 007), so AI Help no longer continues an interview as its "latest conversation" - it had been appending the secret editorial to one. The interviewer gets stage notes written for its side of the table instead of the candidate's on-screen sentence, `GET /api/interview` returns the transcript, and advancing past the debrief no longer counts `at` beyond the last problem.
- **P4-14** — Drafts and notes share one autosave, `useDebouncedAutosave`, because each copy had its own way of losing work. The draft keyed unsaved text on the route, so leaving for a problem that had not loaded yet filed the old problem's code under the new one's name; neither copy ever retried a failed PUT - the text was dropped and nothing on screen said so. The hook writes text only under the scope it was loaded from and is idle while the next problem loads, flushes on scope change and unmount, and writes on `pagehide` - with `keepalive`, or as an ordinary request past the browser's 64 KB keepalive cap, where a keepalive is refused outright and a long draft used to be lost without a word. A failed write is kept and retried with backoff until it lands or a newer write for the same scope supersedes it, and "Not saved - retrying" shows for as long as anything is owed; reset-to-starter drops a queued retry, so a late retry cannot resurrect the draft being deleted. Found on the way: a problem already in the query cache mounted with an empty editor over its saved draft, and the first autosave then wrote over the draft; the editor now always seeds on its first render with a problem.
- **P4-15** — Every answer that arrives late is checked against the scope showing when it arrives, not the scope that asked. Verdicts are checked against a ref of the problem and language on screen - the old guard compared the request with itself, and its test never waited for the verdict. The coach state carries its own scope, so stream events after a switch are dropped. Run and submit errors reset when a request starts and when the scope changes, so an old error cannot hide a newer verdict or follow the user to the next problem. Switching language no longer ends an interview. Run and Submit stay bound while the judge works, as no-ops, because unbound keys fell through to Monaco, which inserts a line; fields that own their keys opt out with `data-shortcuts="local"` - the coach box's capture-phase `stopPropagation` never worked, because the registry listens on the window, whose capture phase runs first. The shell's error boundary resets on navigation, coach mastery refreshes status everywhere, a truncated stream is reported as cut off rather than left `aria-busy`, a leftover Monaco model can no longer show different code from what Submit sends, and Run, Submit and AI Help read the code as of the last keystroke. Each new test was run against the old code and fails there.
- **P4-16** — The clock took the elapsed time off twice - the server's `remainingMs` already excludes it - so a sitting reopened after twenty minutes showed 5:00 instead of 25:00; it now counts down from when the answer arrived. The conversation is read back from `GET /api/interview`'s new `transcript`, because leaving for the workspace to write the code is the normal case and coming back used to start the conversation over. It is seeded once per sitting rather than on every refetch, so a refetch racing a turn cannot remove a line the candidate just watched appear, and a turn still streaming when the screen closes is aborted so it stops costing tokens. Once both problems are done the only thing on offer is "End it and get the debrief"; the old "Move on" there only pushed the index past the last problem. The reply box is read-only rather than disabled while the interviewer answers, so focus stays with the candidate.
- **P6-8** — Four problems accepted the wrong solution their own editorial warns about - a bipartite check that starts only from vertex 0 (two-colour-graph), a null-free traversal (same-shape-trees), an in-order palindrome for a mirror (mirror-tree), greedy longest-word-first (word-break-possible) - and each now has the hidden case that catches it; the auditor's wrong solutions, which passed every old test, fail exactly there. Five generators produced inputs their statements forbid, such as a balance row of 20,001 weights under a 10,000 bound (balance-point, edit-steps, partition-equal-halves, trap-the-rain, first-not-below); the helpers are clamped and a scan of every test finds no violation. The larger change is honesty about timeouts (D21): measured, a quadratic loop at n = 10^4 times out in Python and finishes under Java's JIT, so twelve statements now say which language the trap holds in and name the target complexity for the other, rather than growing inputs to 10^5 on a `tests.json` already at 110 MB (it is 109.9 MB after). Four trap flags - running-median, range-sum-mutable, range-minimum, window-median-stream - are dropped because no honest size defeats the obvious approach, and coin-ways gains the one cheap case that makes its trap real: 2,140,976,929 ways to make 932, which enumeration cannot count. The overflow pitfalls the median editorials warned about get cases that reach them (the old "overflow" case summed to zero), and pair-sum-under-limit's pitfall now gives the true maximum count. About forty example inputs copied from LeetCode (D8) are replaced with invented ones, in the samples and their hand-written copies in the generators. Four examples showed `[]` where the problem answers `null`; nine hint rungs that gave the exact conditions or formula are cut back to the solution's shape; untouched Java starters pass at most one sample; the insert-delete-random editorial says what its checker cannot see; and `docs/CURRICULUM.md` matches `meta.json` on all 171 rows again, with a new **unordered** flag for problems compared as sets rather than by a checker. `docs/AUTHORING.md` gains the rules that would have prevented each of these, and `docs/PROBLEM_FORMAT.md`'s illustrations use invented values too. 73 problems changed; the 48 whose tests changed are one version higher, the 25 whose text alone changed keep theirs (PROBLEM_FORMAT §12), and every one was validated and checked against its generator.
- **P5-13** — A follow-up resends the review it asks about on every question, and only the system prompt was cached; the last turn of history is now a cache breakpoint - the new message never is, because it is the part that changes (D20 updated). A turn stopped mid-think used to be recorded as writing one token, because Anthropic sends the real output count only at the end; it is now charged what it was seen writing plus a thinking allowance, deliberately pessimistic, as a spend cap must be. The estimate under AI Help now includes thinking - billed as output, never shown, and the larger half of a review - and its idea of the prompt's size comes from `@devpromax/shared`, where the server's context builder reads the same caps; the client's copy had put the system prompt at 5,700 characters against a real 9,155, and a server test now fails if the shared figure drifts a tenth from the prompt. Prose turns ask for low effort; reviews keep medium. `claude-opus-5-5` joins the price table with its own cache-read rate, where it had been charged at Fable's price, more than double the real one. Gemini's thinking tokens are counted as output, which is how Gemini bills them.
- **P3-10** — A backup leaves the coach API key out unless `--include-key` is passed, and says so: the key rests in the live database by design (D19), but a backup exists to travel, and it is erased from the file's bytes, not just nulled in its row (`secure_delete`, an in-memory journal, then VACUUM). Restore checkpoints the live database before moving it and keeps its write-ahead log beside the displaced copy - it used to delete that log, which could take away exactly the last work that made someone reach for a backup - and refuses while the app answers `/health`, since on Linux the rename would succeed and the running server would keep writing to the moved file. `db:backup` no longer creates an empty database when there is none, and no longer migrates the file it copies. Submission history pages with a `createdAt|id` cursor, so rows sharing a millisecond are no longer skipped at a page break. The server shuts down cleanly when its console window is closed (SIGHUP), a cancelled stream whose clean-up throws is logged instead of crashing the process, the formatter runs one process per language at a time, and re-verify maps judge failures the way Run and Submit do.
- **P2-17** — The judge answered any batch that stopped early by running every remaining test in a process of its own - right for the test that failed and expensive for the rest: one TLE among twenty hidden tests cost nineteen JVM starts, and those re-runs had no stall watchdog. The batch now restarts at the test after the failure, so a run costs one process per failure plus one; D3 is revised to say so, keeping the isolation it was for. A solution that never finishes loading - a loop at module level, a static initialiser that throws or calls `System.exit` - is recognised by the missing `ready` event and reported once, as TLE or RE with the reason, instead of being run once per test. A `System.exit` in a test is recorded against that test by a shutdown hook, with the frames that called it. Closing the tab cancels the run: a queued run leaves the queue, a running one has its process tree killed, and nothing is recorded, because nobody saw the verdict.
- **P3-9** — The list page, the dashboard and repeated Submits were slow for reasons unrelated to the data they showed. The list stamps only `meta.json` and reuses a directory listing whose freshness is a few stats; the review queue and dashboard use SQL aggregates instead of reading every submission's code through zod; one metadata map is built per request. On this machine `GET /api/problems` fell from about 330 ms to about 20 ms, the dashboard from about 450 ms to about 20 ms, and a repeat Submit's problem load from about 440 ms to under 1 ms. Every mtime cache follows git's "racily clean" rule: Windows stamps files from a clock with ticks of several milliseconds, so a cached read is trusted only if its files were already older than the read by more than a tick, and anything newer is read again - the caches can only be as wrong as no cache at all. The Submit cache holds 8 problems, because every problem's hidden tests in memory is not worth it.
- **P2-18** — Java no longer compiles the thousand-line harness beside every solution: it is compiled once per harness version and compiler into a cache beside the workspaces (not inside them - the startup sweep empties those), built in scratch and renamed into place so a directory that exists is complete, and mounted read-only under Docker. That takes about 0.7-0.9 s off each Java Run on this machine. A user's own ListNode/TreeNode is still explained, now with a line and column, detected from the class files javac writes since there is no longer a duplicate for javac to report. Python's separate syntax-check process is gone from Run and Submit (about 160 ms, and one container start under Docker), because importing the solution already finds the syntax error with its line and column. A Run no longer reads or validates the hidden tests it never uses, and tree conversion in the Python harness is linear.
- **P4-18** — The workspace no longer does work per keystroke or per second that nobody reads: Monaco's options and change handler are stable, the results and testcase panels are memoised, the splitter keeps the drag ratio to itself and reports it once, on release, and the interview clock ticks in its own component instead of re-rendering the whole workspace every second. Every screen but the list is a lazy route behind the shell's existing boundary; the entry fell from 854 KB (266 KB gzip) to 540 KB (170 KB gzip), and the markdown pipeline and highlighter left the first paint. Typing in the problem search re-rendered all 171 rows per character, because the text lived in the list component; the box and its debounce are a component of their own, rows and the filter card are memoised, and a test counts row renders across three keystrokes and requires zero. None of that moved Lighthouse, and the reason was not speed at all: the workspace painted in 0.2 s and lost its points to a layout shift of 0.2. The first-run welcome waited for Settings before drawing, so for every new user it arrived after the page had painted and pushed the whole screen down; with it dismissed the same page scored 97. Like the theme (P4-2), whether it was dismissed is now mirrored into `localStorage` for the first paint - there from the start for someone new, absent from the start for someone this browser saw dismiss it, the server still the source of truth - and Lighthouse reads 97-99 for the workspace and 100 for the list and Progress, from 87-88 and 90.
- **P4-17** — Focus no longer drops to the page when a control removes itself: Clear all moves it to the Filters heading, the empty state's way out to the search box, the welcome's "Got it" to the page heading. `ConfirmDialog` returns focus to whatever opened it - Radix returns focus to a `Trigger`, and this dialog is opened from state and has none, so every confirmation used to drop focus. The list's count is a live region and the table is `aria-busy` while stale rows are shown. "Today" and "yesterday" are calendar days on this machine's clock, through one shared helper instead of two formatters with different cut-offs. The coach's brief will not call one of two equal marks the stronger, and the chart no longer draws its "1" tick twice. Welcome and the reset dialog tell the truth: a Run does mark a problem In progress, a reset also deletes coach conversations and mock interviews, and `npm run db:backup` is how to keep a copy. The command palette says why an action failed and sends one request however fast Enter is pressed; markdown links no longer carry a stray `node` attribute. `ui/` now honestly says which primitives have one caller and why they stay, and variants no screen used were removed, since an option nothing uses has never been checked. Token-drawn checkboxes and radios draw in system colours in forced-colours mode, where the browser had been erasing both the fill and the tick.
- **P7-11** — Streak, calendar, "this week" and the chart's today were UTC days, so evening practice in the Americas counted toward tomorrow and two late-night sessions in India could land on one UTC day and break a streak. Timestamps stay UTC where they are stored; only the bucketing moves. The client sends its IANA zone as `?tz=` (the report link too, so the file agrees with the screen), the server groups days in it - in code, since SQLite knows no zones - and an unknown zone is a 400 rather than a quiet fall back to UTC, which would look like a bug. A client that sends none gets the UTC days it always did.
- **P2-19** — Results the judge could not read - a number too large for JSON, a lone surrogate, which also crashed the Java writer - are reported against their own test instead of vanishing and triggering a re-run, and returned values are no longer walked by zod on the event loop. A checker that throws gives WA, not a 500, and Run, Submit and re-verify share one error mapping. A concealed hidden test's error keeps only its type, because messages like `KeyError: 48213` are the hidden input. javac is forced to English and UTF-8, "public class X" gets advice the user can follow, the Docker failure detector no longer mistakes compile-error text for a missing daemon, and the output cap covers stdout and stderr together, as its doc always said. A StackOverflowError whose unwinding outlasts the budget - four million frames under `-Xss64m` - is reported as the overflow it is rather than as TLE: the one test that failed in the audit's baseline run.
- **P8-7** — The production spec now runs in CI: the ubuntu e2e and nightly jobs build first, and the spec fails in CI when there is no build, where it used to skip - that skip is how `npm start` went untested in CI. Integration test files run one at a time in their own vitest project, `server-integration`: four files at once on four cores measured the machine, not the judge. The whole-catalogue case in `references.integration.test.ts` is opt-in with `DEVPROMAX_CATALOGUE_TESTS=1`; it duplicated `problems:validate` and added about 4.5 minutes to every integration run on the slower machine. `problems:gen --check` now runs on pull requests for the problems they touch, and for everything when generation itself changed; nightly validates the whole catalogue on both OSes and checks the generators, as D23 always said it did. The doctor's interpreter-spawning tests moved to `doctor.integration.test.ts` so `test:unit` stays Node-only, the unused vitest `globals` is gone and the shared alias is declared once (inline projects never inherited the root's), Playwright's Chromium is cached per Playwright version, and `npm run test:coverage` reports v8 coverage without a threshold, because a number that fails the build gets tests written to move the number. Found while the catalogue fixes were being validated: `problems:validate <slug>` validated all 171 problems, because the argument parser dropped index 0 as "the ref after `--changed`" even when there was no `--changed` - so every one-problem check the docs describe had been a five-minute whole-catalogue run. The parser is its own module now, with the test.
- **M5.1** — `docs/API_KEY_TESTING.md`: the procedure for the first real key, written because the audit's last open item is that the live suite has never met the vendor. The live suite runs in two parts, the cheap one first - does the API accept the request (about $0.25), then does the prompt still grade the way the ladder says (about $0.75) - so a refused request costs cents rather than a dollar, with the key read into the shell without echo so it lands in neither the screen nor the history. Then the key goes into Settings with a cap, and ten checks by hand, each with what should happen: the local refusal of an untouched starter, a review that mentions the Run, a prose follow-up, Stop, the solution gate, mastery, the cap, an unknown model, an interview that survives a trip to the workspace. Writing it corrected two things: the live suite's own comment said it cost "a few cents" (about a dollar on Opus 5), and the cap is per conversation - one problem in one language until "New conversation" - rather than per click.
- **P8-8** — Monaco 0.56 pins DOMPurify 3.4.8, affected by GHSA-55q2-fjhq-7xh7 and three other DOMPurify advisories; a root `overrides` entry moves it to 3.4.16 without touching Monaco, and `npm audit --omit=dev` is clean. `@devpromax/server` declares the `zod` it imports rather than borrowing the shared package's. Dependabot opens weekly PRs for npm (minor and patch grouped, majors one by one) and for the Actions. CLAUDE.md's Commands block matches `package.json`, ARCHITECTURE describes what the audit changed, and D3, D12, D15 and D20 carry the new reasoning.
- **P8-9** — A janitorial pass after the audit. `knip` over the three workspaces found three symbols nothing called (`commandAvailable`, `OPTIONAL_FILES`, and `resetSettings` with the settings repository's `reset()`, which only it used); they are gone, as are about thirty `export`s only their own file read and a coach barrel that re-exported a dozen names nobody imported through it. Three statements had their stated bounds lowered or their generators widened for the same reason: running-maximum to 10^4, and word-pattern-match's sentence built from nine-letter words so it actually reaches 2999 characters. product-except-self caps the number of readings with |v| >= 2 rather than hand-waving that the products fit.
- **P6-3** — Batch B is 34 new problems - linked-list 11 of 13, stack 9 (of 12, three seeded), matrix 11 - and the catalogue validates at 79. Two findings worth the record. First, the wire format decides what can be asked: an empty chain is `[]` going in and `null` coming back, which four samples got wrong until the validator said so, and a cycle cannot be expressed at all, which is why P2-15 now sits ahead of this row rather than the two problems being quietly dropped. - **P6-4** — Batch C is 39 new problems and the catalogue validates at 118. Two judge defects surfaced, and neither could have been found by the tests that existed. Checking every stored expectation against an independent implementation - not only against the other language's reference - paid for itself twice more: `next-greater-cycle`'s hand-written sample was wrong, and two `accounts-merge` generator cases violated the problem's own constraint that every account of a person carries that person's name, which left the merged name undefined and only agreed by luck. - **P6-5** — Batch D is 39 problems and the catalogue validates at 157. The D21 check had a hole this batch found: it measured array lengths only, so a problem carrying its size in a scalar - `combinations-of-k` takes n and k and builds its own data - reported a largest input of 0 and warned however large n was. It counts a scalar now, but only a non-negative integer no larger than the stated bound, which is what stops a `target` of a million silencing a size bound of ten thousand. - **P6-6** — Batch E is 12 problems and the catalogue validates at 169. `insert-delete-random` is the catalogue's second `checker` problem and the first where the checker has to _replay_ the operation sequence: `pick` may return any member, so its returns cannot be compared, while `add` and `remove` still have exactly one right answer each - the checker keeps the set as it goes and holds each operation to its own standard. `union-find-sizes` is dropped: `graph-union-find` is the same structure with the same contract, sizes included.

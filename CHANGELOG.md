# Changelog

What shipped, and why. Newest day first.

This is the project's own record rather than a release log: DevProMax is one
local application with no versions to publish, so what is worth keeping is the
reasoning behind each change - the thing a diff cannot carry. Entries are keyed
by the ROADMAP task they close, so the plan and the history point at each other.

It lived in `ROADMAP.md` section 7 until 2026-09-18 (P8-4), by which point fifty
entries had made the plan's last section longer than the plan. The days are
newest first; within a day, entries are in the order they were written, which is
how they arrived in that section and not worth rewriting after the fact.

## 2026-09-22

- **P8-5** — `temp/` is retired on the owner's confirmation, and with it M5: release 1.0. It held the repo's previous life - stubbed DSA notes and a CodeSignal drill kit, archived by P0-1 with `git mv` so the history would survive exactly this. Nothing read it: the only references were the three ignore lists that existed to keep lint, format and typecheck out of it, which go too, since an ignore entry for a folder that is not there reads as a folder someone forgot to create. The files are one `git show 2c01d25:temp/...` away.
- **P2-16** — a second machine is a test suite nobody writes. Two of the three findings were latent everywhere and only surfaced because this machine differs from the first: the word-break generators were never deterministic (string hashing is randomised per process, and nothing pinned it), and the uninterruptible-call test depended on the operating system refusing to commit 80 GB _slowly_. The fix for the first is at the runner rather than in the two generators, because the next author to iterate a set of strings will not know to sort it - and it cost a flag: `-I` cannot be kept, since it implies `-E` and `-E` ignores `PYTHONHASHSEED`. The third finding is the only one that is about speed, and it was settled by timing what a user would write rather than what the reference does: a limit only the bitmask solution can meet grades the machine, not the approach. The regenerated word-break problems are version 2, which is P7-9's drift banner doing the job it was built for.
- **P8-4** — CLAUDE.md still described the state before P8-4 and P2-15 landed, named 169 problems where there are 171, cited decisions D1–D17 of 25, and said Docker and uv were installed nowhere. It now describes two machines, including the rule that a reference needing most of its limit on the slower one is a defect. README's count and the M5 row are corrected with it.
- **P9-2** — the executor interface was kept small in P2-1 so this would be additive, and it nearly was: what Docker changes is _where_ a program runs and _what a path looks like_ from there, so that became a `Launcher` and the two executors became factories over it. The rest was deciding what a container may not do, and making each refusal a test twice - once as a flag in the argument list, because a refactor that drops `--network none` still judges code correctly, and once attempted from inside a real container. Two things were not about Docker at all. Killing the `docker` client leaves its container running, so every kill path now calls an `onKill` hook; and the test for that hook found the stall watchdog killing on every tick between the kill and the child's exit, harmless for a local process and one spawned `docker kill` per tick for a container. The other was the machine: its ntfy watcher pages on every non-zero container exit, which a wrong answer is, so judge containers carry a label and the watcher skips it. Local stays the default - it needs nothing installed beyond the runtimes, and is a second faster per Run.
- **P0-6** — `format:check` had been failing on `main`: 129 files, nearly all problem editorials and statements written after the last format pass, plus the two newest coach prompts. The prompts are now in `.prettierignore` rather than formatted, because they are versioned bytes and Prettier re-marking an emphasis would change what the model is told under a version number that says nothing changed. Everything else is formatted; the changes are emphasis markers, table padding and inline arrays in `meta.json`, which render the same, so no problem version moves (PROBLEM_FORMAT §12).

## 2026-09-18

- **P9-1** — the feature is a _shape_, not a model: almost nothing here is new machinery. The interviewer is the coach's provider seam with a different system prompt, every turn goes through `streamCoachTurn` so the cap and the cancellation are the ones already tested, and the only new table holds five columns and a stage. What had to be decided was smaller and matters more. The sitting advances when the **candidate** says so, never on a timer - an interviewer does not cut someone off mid-sentence because a clock fired, and a screen that had moved on by itself would leave them talking to nobody. The situation goes with the message rather than into history, because it is true _now_; three turns later a stored copy would have the interviewer probing a stage that ended ten minutes ago. "Submitted" means submitted **since the sitting started**, since a problem solved last month is not an answer given today. Ending without a key still ends the interview - and that turned up the one real bug in the screen: the failure was rendered only in the live branch, so pressing "End it" with no key made the whole thing vanish with no explanation at all. The prompt is unversioned on purpose: `PROMPT_VERSION` exists so a number in the database can be traced to a wording, and a conversation that stores no number needs none. Reset-all-progress now clears interviews too, which it should have from the first line - a sitting asking about problems the reset has just marked unsolved is not a record worth keeping. One test lesson: `/interview` draws two entirely different screens depending on whether a sitting is running, and there is one current sitting per database - so the axe audit walked into a live interview started by another project and failed in dark only. The interview spec now has a project of its own, one worker wide and a dependency of the audit, exactly as `settings.spec.ts` does for the theme; and the live screen is audited deliberately rather than by accident. 84 end-to-end tests green.

- **P9-4** — the provider seam held: a third implementation and nothing above `coach/` changed. What it did not hold for was two _contract_ assertions, and both were the contract describing two vendors rather than the invariant. The key "is in a header" became `toContain` rather than `toBe`, because this API spells it `Bearer <key>`. And "the system prompt is not among the turns" is not expressible for the OpenAI chat API, which has no field for it - it is `messages[0]` by definition, so the test now asserts what is actually true there: first, once, and still built separately on our side, because rebuilding it is what breaks caching. The honest part of this task is the pricing table, which is empty: a model on the user's laptop costs nothing and a gateway costs whatever its owner charges, so any number would be a guess presented as a fact, and the two guesses are wrong in opposite directions.
- **P2-15** — the row said "both halves are the same decision", and writing it showed they are not. Making a _cycle_ expressible is letting the wire carry construction instructions: the test says `[[3, 2, 0, -4], 1]`, the harness closes the chain, and the solution is handed a head. Making a _clone_ expressible is letting the wire carry object identity, which it cannot - a copy and its original are the same edge list by the time anything can compare them, so "return a copy" has no observable answer and returning the argument passes. The first shipped and unblocked two problems; the second is dropped with `clone-the-graph`, because the alternative was a node type in the reflection table plus an identity assertion in both harnesses, a fourth `expect` mode serving one problem. Three details worth keeping: the index is consumed rather than passed, so the starter's signature is the truth; Java picks its overload by arity and had to be told the index is not a parameter; and a cyclic argument forces `expect: "return"`, since the encoder refuses to serialise a loop rather than writing forever.
- **P8-4** — the screenshots are generated from the built app by a script rather than cropped by hand, because a README's images go stale silently and a script can be re-run. Two of them needed a real solve behind them: the first workspace shot showed the untouched starter failing its own samples, which is a picture of the app not working. The revision history moved to this file - and moving it turned up that it had two orders in it, an early block written oldest-first and a later one newest-first, so the days here are newest first and the entries within a day are left in the order they arrived rather than rewritten after the fact. `CLAUDE.md` still described M2.1 and twenty problems.
- **P8-3** — one hour of this task went to a single import. `import process from 'node:process'` in a module the server loads stops `npm run dev` from ever starting the API under `tsx watch` on Windows - no error on either stream, the child process alive and not listening, and only the web half of `concurrently` up. The e2e suite failed in a way that looked like twenty broken features; it was one line, and the fix is the global `process`, which is what every other file here already uses. A comment in `doctor.ts` says so. Two design notes worth keeping: backup uses `VACUUM INTO` rather than copying the file, because a live SQLite database is three files and the copy would be missing the write-ahead log; and restore moves the displaced database aside rather than deleting it, because the person running it has usually just realised something went wrong. Also de-flaked `coach.spec.ts`, which typed into Monaco under load and got "class Soltion" - it pastes now, like every other spec.
- **P8-2** — every number in this row is now a test rather than a note, which is the point - a measurement taken once is a claim about one afternoon. The 500-row test asserts the row _count_ as well as the timing, so "we decided not to virtualise" cannot quietly become "someone virtualised it". The judge load test goes through `runProblem` rather than `runProblemUnqueued`, which every other integration test uses, because the queue is the thing under test. Lighthouse drives Playwright's own Chromium rather than whatever browser the developer has installed: two machines scoring different Chromes are not comparable. It runs as its own CI job on the built output, since scoring a Vite dev server measures the HMR client and an unbundled module graph that nobody ships.
- **P8-1** — the suite found three things nothing else would have. The stand-in vendor URL that `coach.spec.ts` relies on was `/__no_vendor__`, outside `/api`, and worked only while nothing served a UI behind the API - the moment `apps/web/dist` existed the server answered it with the single-page app's `index.html`, and a 200 full of HTML is not a refusal; it is under `/api` now, where the client-header rule runs before any route. The list's "Clear all" had been left behind by P7-7 and did not clear the bookmark filter. And the production spec was failing purely because the built output in the working tree was two hours old, which is worth remembering: `test.skip(!built)` means that spec silently measures whatever was last built. On the budget: two flaky tests per run, not zero, because zero means a single hiccup on a shared runner blocks a merge and the suite grows `test.skip`s instead of getting more reliable.
- **P7-9** — drift is reported, never acted on. A generator seed that moved is not a reason to un-solve somebody's problem, so the status stays, the row says the bar moved, and the dashboard counts these apart from the solved total instead of deducting them. Re-verify is deliberately an ordinary submit of the stored code rather than a special comparison: the honest way to find out whether it still passes is to run it, and the result belongs in the archive like any other. Two e2e failures turned up while running the full suite for the first time in this block, and both were mine: P7-1 made hint reveals persist, so `flows.spec.ts` asking for "Show the first hint" could only ever pass once per database (it now reveals whichever rung is next, and tolerates a ladder that is already open), and P7-3 turned the submissions table into a list, so a `getByRole('row')` in the same spec matched nothing. The row-by-row filter assertion there was also racing the refetch and is now a single retrying "no row fails to match". Lesson for the rest of this block: run the whole Playwright suite, not just the axe audit.
- **P7-8** — no schedule table. An accepted submission already is a pass, so the queue is a count of them plus arithmetic - which means re-solving a problem advances it with no extra write to get out of step, and the queue was already correct for every solve made before this existed. The ladder deliberately stops at three weeks: an interval that keeps doubling eventually means never, and the point past a month is upkeep. Mastered doubles each step and no more, because a solution you cannot reproduce in six weeks is not one you know. Review mode and interview mode want exactly the same thing from the statement panel, so the prop stopped being called `interviewMode` and started saying what it does: `hideAssistance`. A screen that has quietly removed two tabs needs to say so and needs a way out, which is why review mode has a banner rather than just a URL parameter.
- **P7-7** — the palette is a combo box, not a menu of buttons. Focus has to stay in the text field - the user is still typing - so the highlight is `aria-activedescendant` and the rows are `role="option"`; the click handler on a row that can never hold focus is the one lint exception in the file, with the reason written next to it. `Ctrl+K` is Monaco's chord prefix and this takes it: a palette that is not reachable from inside the editor is not reachable from where people work. The recommendation answers with a reason as well as a problem, and the reason names which signal it used - the coach's scores, or simply what is least finished - because "go and do graph" with nothing behind it is an assertion rather than advice. Bookmarks went in their own table rather than as a column on progress: a problem can be starred before it has any progress row, and a star survives a progress reset.
- **P7-6** — two decisions carry this one. The hints and the editorial are _removed_ while the clock runs, not disabled - the mode exists to practise without the option, and a greyed-out tab is still a tab you can see and think about. And `solve_ms` is nullable rather than zero-defaulted, because an untimed submission and an instant one are different facts; P7-10 calibrates ratings against this column, and counting every untimed submit as zero would make every problem look easy. The coach's half is prompt `v4`, gated on the flag: most practice is not against a clock, and a paragraph about explaining yourself on every review would be padding. The section asks for the complexity _with its reason attached_, which is the part people lose interviews on.
- **P7-5** — the export was the part that needed a decision rather than code. A skills report is a file that leaves the machine, so it carries what the user can do and nothing they wrote - no code, no notes - and the HTML form fetches nothing at all: no script, no stylesheet link, no image, no absolute URL, because anything it requested would either fail on the reader's machine or tell a third party it had been opened. A test asserts each of those absences. Two smaller judgements: a streak is not broken by a quiet morning, since the day is not over, and the rubric table shows how many reviews are behind each average, because "your weakest topic" picked out of one anecdote sends someone off to practise the wrong thing. Opened editorials are counted and said out loud beside the solved count rather than folded into it. The axe audit passes on the new screen in both themes.
- **P7-4** — the note search is the half worth explaining. Titles and patterns are what the catalogue calls a problem; a note is what the user calls it - "the one where the window shrinks from the left" - and that is usually the name they can actually remember. It goes through the database rather than reading every note into memory, and through `instr` rather than `LIKE`, because the search box contains whatever someone typed and `%` in it is a per cent sign. One thing this ran into and did not change: reset-all-progress deliberately keeps notes, which an existing test states outright. That is consistent rather than inconsistent with P7-1 and P7-2 losing their state on a reset - those are derived from the activity log, which is the record of practice; a note is the user's own writing.
- **P7-3** — the interesting part was not the diff - P7-2 had already built it - but the restore. Putting Java in the editor while the editor is in Python mode is putting a syntax error there, so a restore carries its language, and the render-phase block that re-seeds the editor on a language change had to be told that this particular change already has its code. It also stops sending the user back to the Description when the change came from a restore: they pressed a button on the Submissions tab, and answering by moving them somewhere else is a strange way to confirm it worked. The list is a `ul` now rather than a table - every row is a single button and there are no column headers left to justify one.
- **P7-2** — the editorial lock now opens from the inside. A gate the user cannot open on their own machine is one they work around by opening the repository, which teaches them nothing and records nothing; a gate that costs a confirmation and a line on the progress page is a gate that still means something. The diff is hand-written rather than a dependency - forty lines of LCS over two files a person wrote by hand, where a package would bring word-level diffing, patch parsing and a renderer none of this needs. It is line-level on purpose: the interesting difference between two solutions is structural, and highlighting characters inside a line that was rewritten says nothing. Two things the tests caught: a `<section>` with language buttons in it needs a label, because the workspace toolbar's buttons read identically; and the syntax highlighter splits `class InJava` across two spans, so a test that queries for the phrase finds nothing.
- **P7-1** — the revealed-hint count is derived from the event log rather than stored beside it. A `hint_reveals` table would have held exactly what those rows already say, and the two would then need keeping in step - including through reset-all-progress, which clears events and would have left a user with no history and four hints still open. The request body names the rung, not an increment, which is what makes a doubled click and a stale tab both harmless. The half that was not obvious from the row: "treats the static ladder as canonical" cannot be done by telling the coach what the user has _read_ - it has to be told where the author was pointing _next_, or it will start someone down a second, equally valid approach halfway through and contradict the hint they unlock a minute later. So the coach now receives one unread rung, marked secret like the editorial and with its own sentence about why: handing it over verbatim spends a hint the user has not spent. That changes the advice, so `PROMPT_VERSION` is `v3` and `v2` stays on disk.
- **P6-7** — 338 regenerations at two fresh seeds, no disagreement between the Python and Java references - the pipeline's per-generation cross-check (D9) holds under seeds it has never seen. What the review pass caught, the pipeline could not have: a sample with no name reads as "Sample 3" in the results panel, a size bound is not tested when the only large thing in the input is a scalar, and a Constraints section can bound `words` while leaving `start` and `target` unstated. Two of those are now validator rules. The fourth item on the row, calibration by solving time, is impossible before anyone has solved anything under a timer; it is P7-10 now, sequenced after P7-6, rather than quietly skipped.
- **P6-0** — seven new validator rules, and every one of them was a defect the seed catalogue already had - which is the argument for checking them mechanically. Two were harder than they looked. The stated-constraint check (D21) has to tell a _size_ bound from a _value range_: a first version read `-10^9 <= values[i] <= 10^9` as a claim about how much input there is and flagged every problem in the catalogue. The no-code-in-hints check has to look for structure rather than keywords: a first version matched `for ... :` and rejected the sentence "two things are being asked for: how often each value occurs". The duplicate-sample rule is enforced in the pipeline as well as the validator, because the generator is where the duplicate came from. pair-sum-index now generates at 10^5 with a constructed one-pair case rather than a quadratic rejection loop, which is what makes its editorial's "the quadratic times out" true; shift-right-in-place's claim was lowered to 10^4 instead, since its trap is space and no size proves that. Along the way the coach's connection test turned out to call any 200 a success - a stand-in vendor that answered with an HTML page read as "connected" - so an unreadable model list is now a failure, which is P5-10's row but this task's find.
- **P4-13**, and M2.1 with it. The memoisation needed three changes rather than one: `memo` on the two panels does nothing while the caller builds the coach element inline, and a callback closing over `useCoach`'s wrapper changes identity every render even though every function inside it is stable. The a11y pass added here found a real `serious` violation on its first run - the results detail pane scrolls and could not hold focus - and the fix needed the `jsx-a11y` rule relaxed for grouping roles, because axe and that rule disagree by default and both are right. Three of the four end-to-end failures chased today were the same thing wearing different hats: the language is a _setting_, shared by every spec and every earlier run, so a test that does not choose one is testing whatever the last test chose.
- **P6-1** — `docs/CURRICULUM.md` plans 175 problems rather than the 200 the original row named, and the cut is the point - a problem that teaches nothing the one before it did not is worse than no problem, and the tables were trimmed twice on that rule. `patterns` is a closed enum now (`packages/shared/src/patterns.ts`), which immediately found four spelling variants in twenty problems, and `order` must be unique within a topic, which found eight seeded problems whose numbering disagreed with the path they belong to. The scaffold had to stop writing `TODO` into `patterns`: with an enum, a placeholder there makes `meta.json` unparseable and hides every other thing the validator would have said, so it guesses `one pass` and the CLI says so in step 0.
- **P2-14** — measured before and after on the seed - the list path went from 122 ms to 5 ms cold and 2 ms warm, and `problems:validate` from 34 s to 15 s. Three changes did it: the list reads `meta.json` only, nothing the API serves parses the hidden tests (the judge asks for them by name), and the cache is keyed on modification time in every environment rather than switched on by `NODE_ENV`. The hidden pool is dropped _before_ zod rather than after, which is where the cost actually was. `--changed` narrows the reference runs and never the static rules, because the cross-problem checks are exactly the ones a diff cannot see. `problems:gen --check` closes the gap where an edited generator with a stale `tests.json` passed everything, and it refuses to run on the wrong Python minor rather than reporting a difference that means nothing - which is what `problems/GENERATED_WITH` is for.
- **P6-2** — Batch A is 45 problems across arrays, hashmap, sorting and binary-search - 28 written here on top of the 17 seeded ones, and the catalogue validates at 48. Two decisions worth recording. The Hard references were checked against a naive implementation on 400 random cases each _before_ generation, not only against each other: two independently written references agreeing is good evidence and not proof, and the two-heap lazy deletion in window-median-stream is exactly the kind of algorithm where both languages can be wrong the same way. And median-of-two-sorted loses its trap flag in `docs/CURRICULUM.md`: merging two sorted series is O(n + m), which finishes comfortably at any input size whose `tests.json` is a sane weight, so there is no honest maximum-size case that the obvious approach cannot complete - the statement names the logarithmic target instead of claiming a timeout that would not happen (D21). Three statements had their stated bounds lowered or their generators widened for the same reason: running-maximum to 10^4, and word-pattern-match's sentence built from nine-letter words so it actually reaches 2999 characters. product-except-self caps the number of readings with |v| >= 2 rather than hand-waving that the products fit.
- **P6-3** — Batch B is 34 new problems - linked-list 11 of 13, stack 9 (of 12, three seeded), matrix 11 - and the catalogue validates at 79. Two findings worth the record. First, the wire format decides what can be asked: an empty chain is `[]` going in and `null` coming back, which four samples got wrong until the validator said so, and a cycle cannot be expressed at all, which is why P2-15 now sits ahead of this row rather than the two problems being quietly dropped. Second, checking every stored expectation against an independent implementation - not just the other language's reference - paid for itself: `next-greater-cycle`'s hand-written sample claimed the trailing 2 of `[3, 8, 4, 1, 2]` wraps to the 8 when it wraps to the 3. Both references were right and the sample was not, which is the one failure mode two agreeing references cannot catch. Three recurring shapes are now stated in editorials rather than assumed: a recursive flood fill is ten thousand frames deep on a full grid, so every grid reference uses an explicit stack; a monotonic stack's invariant is what makes its inner loop linear; and `zero-the-cross` is a space trap, so its statement names the `O(1)` target and claims no timeout (D21).
- **P6-4** — Batch C is 39 new problems and the catalogue validates at 118. Two judge defects surfaced, and neither could have been found by the tests that existed. The Java harness encoded a returned or mutated tree through an `ArrayDeque`, which refuses null elements - and the level-order format queues a null for every absent child, so every tree that was not perfect came back as a NullPointerException from inside the harness; P2-12 had covered trees as arguments and lists as returns, and `flatten-to-chain` is the first catalogue problem to hand a tree back. The generator's cross-check reporter then hid it: `JSON.stringify(undefined)` is `undefined`, so its `.slice(0, 200)` threw on any case with no `actual`, turning the report about the disagreement into a TypeError about `.slice`. Both are fixed with tests. Checking every stored expectation against an independent implementation - not only against the other language's reference - paid for itself twice more: `next-greater-cycle`'s hand-written sample was wrong, and two `accounts-merge` generator cases violated the problem's own constraint that every account of a person carries that person's name, which left the merged name undefined and only agreed by luck. Seven curriculum rows changed, each for a stated reason: two heap problems dropped as duplicates, two trap flags removed where the obvious approach finishes at every legal size, `widest-level` narrowed because the gap-counting version's answer exceeds the wire's 2^53 bound, `serialise-tree` moved from `operations` to `function` because operations mode hands arguments over undecoded, and `clone-the-graph` blocked. `reorganise-string` is the catalogue's first `checker` problem (D6).
- **P6-5** — Batch D is 39 problems and the catalogue validates at 157. The D21 check had a hole this batch found: it measured array lengths only, so a problem carrying its size in a scalar - `combinations-of-k` takes n and k and builds its own data - reported a largest input of 0 and warned however large n was. It counts a scalar now, but only a non-negative integer no larger than the stated bound, which is what stops a `target` of a million silencing a size bound of ten thousand. Two problems had to be widened to satisfy the ten-hidden-test rule at all: `generate-brackets` as "n pairs" alone has nine possible inputs, and `n-queens-count` twelve, three of each taken by the samples - the first gained a depth limit, which is a better problem for it, and the second went to n = 13, which the reference counts in under a second. Five more curriculum flags were corrected for the usual reason: the obvious approach finishes at every legal size, so the statement asks for the space bound and claims no timeout. The checking discipline stayed as it was, and earned its keep again - every answer in backtracking was checked against itertools, `regex-match` against Python's own `re.fullmatch`, and the bit problems against a plain count over the binary text.
- **P6-6** — Batch E is 12 problems and the catalogue validates at 169. `insert-delete-random` is the catalogue's second `checker` problem and the first where the checker has to _replay_ the operation sequence: `pick` may return any member, so its returns cannot be compared, while `add` and `remove` still have exactly one right answer each - the checker keeps the set as it goes and holds each operation to its own standard. `union-find-sizes` is dropped: `graph-union-find` is the same structure with the same contract, sizes included. Three generators needed widening to clear the ten-hidden-test rule and one - `window-maximum` - needed narrowing, because two maximum-size cases put `tests.json` past the 2 MB the validator allows for a reviewable diff; one such case is enough to make the point and the second was only weight.
